In `src/components/schedule/publish-button.tsx`, modify the `handlePublish` function.

After the existing `if (result.success)` block (lines 51-54), before `onPublished?.()` and `setOpen(false)`, add a check for sync failures:

```typescript
if (result.success) {
  toast.success(`Published ${result.count} entries`)

  // Surface GCal sync failures as warnings (sync is best-effort per D-05)
  if (result.syncResult && !result.syncResult.success) {
    const failedParents = result.syncResult.parentResults
      .filter(pr => pr.error)
      .map(pr => `${pr.parentId}: ${pr.error}`)
    if (failedParents.length > 0) {
      toast.warning(`Calendar sync failed: ${failedParents.join("; ")}`, {
        duration: 10000,
      })
    }
  }

  onPublished?.()
  setOpen(false)
}
```

Key points:
- Keep the existing success toast for DB publish — always shows
- Add a separate `toast.warning` (not error) only when syncResult has parent errors
- Use `duration: 10000` (10 seconds) so the warning stays visible long enough to read
- The `SyncResult` type is already imported transitively through the publishDraft return type — no new import needed. If TypeScript complains, the type is inferred from the Server Action return type.

Do NOT change any other part of the component. Do NOT change the disabled state logic, dialog structure, or draft count logic.
