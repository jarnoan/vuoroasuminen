```typescript
import { pgTable, text, timestamp } from "drizzle-orm/pg-core"

export const userGoogleTokens = pgTable("user_google_tokens", {
  email: text("email").primaryKey(),
  refreshToken: text("refresh_token").notNull(),
  updatedAt: timestamp("updated_at", { mode: "date" }).notNull().defaultNow(),
})
```

Why these exact choices (do not change them):
- `email` (text PK) matches the `ownerEmail` lookup pattern used by `buildGCalClient` in Plan 06 — no UUID needed; email IS the natural key (per D-01 / Pattern 5).
- `text("refresh_token")` (snake_case DB column, camelCase `refreshToken` TS property) matches existing project conventions in `src/db/schema/auth.ts` line 28 (`refresh_token: text("refresh_token")`).
- `{ mode: "date" }` on the timestamp matches the existing convention in `src/db/schema/domain.ts` line 21 — keeps Date objects flowing through queries instead of strings.
- `.notNull()` on `refreshToken` is correct because the callback route (Plan 04) ONLY inserts when `provider_refresh_token` is non-null (otherwise it redirects to /auth/error per SAUTH-06). A null row would never be inserted.

Do NOT add: an FK to `users` (Phase 9 RLS work), an `access_token` column (always exchanged at use-time), a `provider` column (Google is the only provider), or a `userId` UUID PK (email is the natural key per D-01).
