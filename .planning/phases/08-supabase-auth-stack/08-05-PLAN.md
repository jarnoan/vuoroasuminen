<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser cookie → Server Component (header) | Reads session via `getUser()`; spoofed cookies fail JWT verification. |
| Browser form submit → signOutAction | The action is a "use server" function; only authenticated browsers reach it (gated by middleware), but the action does not check auth itself — signOut on a missing session is a no-op. |
| Browser form/RPC → Server Action (toggleCell, etc.) | Every Server Action calls `requireAuthorizedParent()` first; throws on unauth or non-parent email. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-05-01 | Spoofing | Header impersonation via spoofed cookie | mitigate | Header uses `supabase.auth.getUser()` (not `getSession()`) — JWT validated server-side. The header rendering an attacker's name from a spoofed cookie is impossible. |
| T-08-05-02 | Elevation of Privilege | Server Actions executed by non-parent users | mitigate | `requireAuthorizedParent()` (Task 3) checks the JWT-verified email against `config.parents.some(p => p.email === email)` and throws `"Forbidden"` otherwise. Phase 8 keeps the same allowlist as v1.0; Phase 9 RLS-02 adds defense-in-depth at the DB layer. |
| T-08-05-03 | Information Disclosure | XSS via user_metadata fields rendered in header | mitigate | `user.user_metadata?.full_name` is rendered inside JSX `{fullName}` — React's default escaping prevents script injection. `avatar_url` is passed to `next/image src` which validates URL format (would 404 on a non-image). Cast `as string | undefined` does not weaken React's escaping. |
| T-08-05-04 | Denial of Service | signOutAction infinite redirect | accept | `redirect("/")` from a Server Action invoked from a form action is a single navigation event; the home page does not redirect signed-out users back. No loop possible. |
| T-08-05-05 | Repudiation | Sign-out leaves stale Auth.js cookie | accept | The header form only signs out of Supabase. Auth.js cookies (`next-auth.*`) may persist in the browser but are ignored by the new middleware (no Auth.js consumer reads them anymore) and will be cleaned up in Phase 10 when Auth.js is removed entirely. STATE.md notes the Auth.js cookies use a different prefix from Supabase's, so no cookie-name collision. |
| T-08-05-06 | Tampering | Helper rename breaks existing callers | mitigate | Task 3 explicitly preserves the helper name and the throw messages. The verify step asserts all 7 existing Server Action exports remain present. |
</threat_model>
