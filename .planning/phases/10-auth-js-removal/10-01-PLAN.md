    ```sql
    -- Phase 10 / CLEAN-02 — Drop Auth.js tables in FK-reverse order.
    --
    -- DESTRUCTIVE: removes all rows in users, accounts, sessions, verificationTokens.
    -- Pre-flight: confirm user_google_tokens has at least one row per active parent
    -- BEFORE running this migration. Both parents will need to re-sign in immediately
    -- after deploy regardless, but data loss in user_google_tokens would break GCal sync.
    --
    -- Run inside a transaction so a partial failure rolls back cleanly.
    BEGIN;

    DROP TABLE IF EXISTS "verificationTokens";
    DROP TABLE IF EXISTS "sessions";
    DROP TABLE IF EXISTS accounts;
    DROP TABLE IF EXISTS users;

    COMMIT;
    ```

    Notes for the executor:
    - `verificationTokens` and `sessions` are quoted because Drizzle defined them with camelCase names (pgTable("verificationTokens", ...) and pgTable("sessions", ...)). Postgres lowercases unquoted identifiers, so unquoted DROP statements would target a non-existent `verificationtokens` and silently no-op when wrapped with IF EXISTS.
    - `accounts` and `users` are unquoted because their Drizzle names are already lowercase.
    - IF EXISTS is intentional: makes the migration idempotent if rerun.
    - Transaction wrapper means a permission error on table 3 rolls back tables 1 and 2.
  </action>
