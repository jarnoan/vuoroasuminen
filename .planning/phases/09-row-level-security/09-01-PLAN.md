<objective>
Consolidate the browser-side Supabase client to a thin re-export of `createBrowserClient` from `@supabase/ssr`, and update the two callers that still use the old zero-argument signature so they pass `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` explicitly.

Purpose: Without this change Realtime connects to the WebSocket as the `anon` role (the current `@supabase/supabase-js` client has no cookie storage). Once RLS policies are added in plan 03, Realtime would silently stop delivering events. Switching to `@supabase/ssr`'s `createBrowserClient` makes the client read the Supabase session from cookies, so the WebSocket handshake carries the authenticated JWT and Realtime evaluates the user's RLS SELECT policy. Implements D-03 and D-04 from CONTEXT.md, addresses Open Question #1 / Assumption A2 from RESEARCH.md (zero-arg callers must be updated to two-arg calls).
