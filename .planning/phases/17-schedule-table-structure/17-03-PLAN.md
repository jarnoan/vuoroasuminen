  <how-to-verify>
    1. Start the dev server: `npm run dev` (or use the existing running instance). Sign in as one of the configured parents.

    2. Open the schedule view at a desktop viewport (≥ 1024px wide, e.g. resize browser to ~1280×800).

       Verify:
       a. Above each Monday in the visible schedule window, a row reads exactly `Viikko N` where N is the ISO week number for that Monday. Pick a Monday with a known date and confirm against an external reference (e.g. https://www.epochconverter.com/weeks/2026 or any ISO-week calculator) that the number is correct.
       b. The label appears above the FIRST visible Monday too — not only above Mondays after the first.
       c. The label uses small, muted typography (visually consistent with other secondary labels in the UI; e.g. the empty-cell "—" buttons).
       d. The previous hairline (1-pixel border-colored separator) is no longer present anywhere in the table.

    3. While still on desktop, scroll the page using the page scrollbar (NOT a scrollbar inside the table).

       Verify:
       a. The whole page (header, toolbar, table, ExtendPanel, ClearPanel) scrolls as a single unit. There is NO separate inner scrollbar around the schedule table.
       b. As the page scrolls past the table's first row, the `<thead>` (with "Päivä", child names, "Muistiinpanot") sticks to the top of the viewport and remains visible until the table itself scrolls out.
       c. The toolbar and header scroll away before the thead becomes sticky — this is intentional per D-08.

    4. Reload the page (Cmd+R / Ctrl+R) on desktop.

       Verify:
       a. After load, today's row is visible AT THE TOP of the visible table area — not centered in the viewport.
       b. Today's yellow highlight is NOT obscured by the sticky thead — at least the full row height of today is visible below the thead.
       c. If today's row appears clipped (top half hidden behind thead) or floats too low (large gap between thead and today), record the gap size. The fix is a follow-up plan adjusting `scroll-mt-10` to `scroll-mt-8` (smaller offset) or `scroll-mt-12` (larger offset).

    5. Resize the browser window to a mobile viewport (≤ 430px wide; in Chrome DevTools use the iPhone 14 preset or similar).

       Verify:
       a. The schedule table still fits within the viewport (no horizontal scroll regression from v1.4).
       b. Scrolling the page scrolls everything together, just like on desktop now.
       c. The `<thead>` is sticky on mobile as well — same behavior as v1.4.
       d. The "Viikko N" labels also appear above each Monday on mobile.

    6. (Optional but recommended) Test on a physical iOS Safari device or in Safari Technology Preview to confirm there is no `position: sticky` regression — STATE.md notes that an ancestor `overflow-hidden` could break sticky on iOS. The dashboard-shell does NOT have `overflow-hidden`, but a physical-device check is the only definitive proof.

    Map findings to Phase 17 success criteria:
      - SC-1 (week label above each Monday for every week) ↔ Step 2.
      - SC-2 (desktop full-page scroll, no inner container) ↔ Step 3.
      - SC-3 (desktop sticky thead matches mobile) ↔ Steps 3b, 5c.
      - SC-4 (mobile scroll unchanged from v1.4) ↔ Step 5.

    Report any failures with: viewport size, browser, specific success-criterion ID that failed, and a screenshot or short description.
  </how-to-verify>
