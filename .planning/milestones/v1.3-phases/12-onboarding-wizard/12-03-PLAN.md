<threat_model>
## Assets at Risk

- **Client bundle correctness** — wrong prop wiring could cause silent display bugs (e.g., parentId rendered instead of human-readable name)
- **Realtime updates** — props are static per render; the realtime channel may push entries referencing parent ids that must still resolve to a display name

## Threat Actors

- **End user (low threat)** — sees the dashboard; relies on prop-driven rendering to label cells correctly
- **Misconfigured caller** (developer error, not an attacker) — passes undefined parents to a child component

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-17 | Spoofing | ScheduleCell display name mismatch | mitigate | Prop is required (non-optional) in the typed interface; tsc rejects a missing prop. The `??` fallback to `parentId` is preserved so an unrecognized id still renders something rather than crashing. |
| T-12-18 | Tampering | Client mutation of `parents` array | accept | React props are immutable by convention; no codepath mutates the array. A malicious browser console call could overwrite local state, but only affects the attacker's own view — no server-side impact. |
| T-12-19 | Information Disclosure | Parent email leaked into client bundle | mitigate | The dashboard page maps `config.parents` to `parentsForUI` keeping only `id` and `name` — email/calendarId/ownerEmail never reach the client component tree (data minimization). Verify with `grep "email\\|calendarId\\|ownerEmail" src/components/schedule/schedule-cell.tsx src/components/schedule/stats-panel.tsx src/components/schedule/clear-panel.tsx` returning 0 hits. |
| T-12-20 | DoS | Re-rendering on every parents prop change | accept | useMemo dependency array includes `parents` where used; React strict-mode double render is acceptable for a two-user app. |
| T-12-21 | Elevation of Privilege | Client supplying its own parents prop via state injection | accept | Display-only; mutations still go through Server Actions which independently validate via requireAuthorizedParent + getAppConfig (Plan 02). |

## ASVS L1 Controls Applied

- **V8.3.1** (Data minimization on client) — only `id` + `name` cross the server/client boundary, not email/calendar IDs.
- **V14.2.1** (Component inventory) — no new dependencies; only prop rewiring.

No high-severity unmitigated threats.
</threat_model>
