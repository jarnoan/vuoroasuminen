## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline badge padding, gap within input+icon combos |
| sm | 8px | Between label and input, between list items in children name list |
| md | 16px | Padding inside cards, gap between form fields |
| lg | 24px | Section padding within a wizard step, gap between heading and form |
| xl | 32px | Vertical separation between wizard step sections |
| 2xl | 48px | Top/bottom padding of the wizard container |
| 3xl | 64px | Not used in this phase |

Exceptions: Touch target for add/remove child row button: minimum 44px height (accessibility requirement, WCAG 2.5.5). Step indicator dots: 32px wide (8px per inactive dot, 32px for active dot with label visible).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 |
| Label | 14px | 400 (regular) | 1.4 |
| Heading (step title) | 20px | 600 (semibold) | 1.2 |
| Display (page title / completion screen) | 28px | 600 (semibold) | 1.2 |

Source: Matches existing app patterns — `h1` at 4xl/bold (`text-4xl font-bold`) on sign-in page, body at default 16px, label at 14px (`text-sm`) throughout. Wizard caps heading at 20px (step title) to keep visual hierarchy distinct from the app title.

## Color

Color tokens are defined in `globals.css` as OKLCH CSS custom properties. The wizard uses only semantic token names, not raw hex values.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` (oklch 1 0 0, white) | Page background, wizard container background |
| Secondary (30%) | `--card` / `--muted` (oklch 1 0 0 / oklch 0.97 0 0) | Step content card background, calendar ID read-only field |
| Accent (10%) | `--primary` (oklch 0.205 0 0, near-black) | Primary CTA buttons only, active step indicator |
| Destructive | `--destructive` (oklch 0.577 0.245 27.325, red) | Validation error messages, remove child button |

Accent (`--primary`) is reserved for:
- "Jatka" (Continue) button at the end of each wizard step
- "Tallenna ja jatka" (Save and continue) button on the review step
- Active step indicator dot

No other elements use `--primary` as background. Outline and ghost variants use `--border` and `--foreground`.

Muted foreground (`--muted-foreground`) is used for:
- Helper text below inputs (instructions, format hints)
- The read-only calendar ID display field text
- Step indicator labels for completed/inactive steps

## Wizard Layout Contract

### Overall layout

```
┌──────────────────────────────────────────┐
│  Header (existing app header component)  │
├──────────────────────────────────────────┤
│  Step indicator (1–4, horizontal)        │
├──────────────────────────────────────────┤
│  Step content card                       │
│  ┌────────────────────────────────────┐  │
│  │  Step heading                      │  │
│  │  Form fields                       │  │
│  │  Validation alerts (inline)        │  │
│  │  [Back]           [Jatka →]        │  │
│  └────────────────────────────────────┘  │
└──────────────────────────────────────────┘
```

- Wizard is centered, max-width 560px, with `px-6` padding on mobile.
- Existing `<Header>` component wraps the page (reuse, no changes needed).
- Step content card: `bg-card rounded-lg border p-6 space-y-6` (matches existing card pattern from auth error page and sign-in page).
- Navigation row: `flex justify-between items-center pt-4 border-t mt-6`.

### Step indicator

Horizontal, 4 steps. Pattern: numbered dots with text label.

```
● Step 1  —  ○ Step 2  —  ○ Step 3  —  ○ Step 4
Perhetiedot    Kalenteri    Tarkista     Valmis
```

- Active step: `--primary` filled dot, semibold label.
- Completed step: checkmark icon (lucide `Check`), muted foreground label.
- Upcoming step: empty dot with border, muted foreground label.
- Connecting line: `--border` 1px horizontal rule.
- Step indicator is non-interactive (not clickable) — navigation is linear via Back/Continue buttons only.

### Step 4 — Setup complete screen

Full-width centered layout (no card border), using Display typography for the heading. No Back button. Single CTA to dashboard.

## Step-by-Step Interaction Contract

### Step 1 — Perhetiedot (Family data)

**Fields:**
1. Parent A name (pre-filled from Google display name, editable) — `Input`
2. Parent B name — `Input`
3. Parent B email — `Input` type="email"
4. Children names — dynamic list: `Input` per child + "Lisää lapsi" (Add child) Button (variant=ghost) + remove icon button per row (lucide `X`, size=sm)
5. Schedule start date — `Calendar` (shadcn date picker, restricted to Mondays only)
6. First parent — `RadioGroup` with two options (Parent A name / Parent B name)

**Validation errors** shown with shadcn `Alert` (variant=destructive) inline below the offending field:
- Parent A name empty: "Nimi ei voi olla tyhjä"
- Parent B name empty: "Nimi ei voi olla tyhjä"
- Parent B email invalid format: "Syötä kelvollinen sähköpostiosoite"
- Parent B email same as Parent A: "Toisen vanhemman sähköposti ei voi olla sama kuin omasi"
- No children added: "Lisää vähintään yksi lapsen nimi"
- Child name duplicate: "Tämä nimi on jo lisätty"
- Start date not selected: "Valitse aloituspäivä"
- Start date not a Monday: "Aloituspäivän on oltava maanantai"
- First parent not selected: "Valitse kumpi vanhempi aloittaa"

**CTA:** "Jatka" (Button variant=default)
**Back:** Not shown on Step 1 (first step).

### Step 2 — Kalenterit (Calendar IDs)

**Fields:**
1. Parent A calendar — `Combobox` (calendar name list from calendarList.list API call, auto-selects) + read-only `Input` showing the raw ID below
2. Parent B calendar — `Input` for paste (fallback only since Parent A likely does not have access to Parent B's private calendar via calendarList.list)
3. Collapsible instructions block (lucide `ChevronDown` toggle): "Mistä löydät kalenterin tunnuksen?" with 5-step numbered list

Loading state for calendarList.list: spinner (lucide `Loader2` animate-spin) inside the Combobox trigger while the Server Action resolves.

**Validation errors:**
- Parent A calendar ID empty: "Valitse tai syötä kalenterin tunnus"
- Parent B calendar ID empty: "Syötä toisen vanhemman kalenterin tunnus"
- ID format obviously wrong (contains spaces or http://): "Tarkista kalenterin tunnus — se ei näytä oikealta"
- Live calendarList.get verification failure (soft warning, non-blocking): Alert variant=default: "Kalenterin tunnusta ei voitu vahvistaa — tarkista se ja jatka, jos olet varma"

**CTA:** "Jatka" (Button variant=default)
**Back:** "Takaisin" (Button variant=ghost)

### Step 3 — Tarkista (Review)

Read-only summary of all data entered. No form fields. Uses a definition list layout:

```
Sinä (Parent A name)        sinun@email.com
Toinen vanhempi             toinen@email.com  (Parent B name)
Lapset                      Emma, Mikael
Aloituspäivä                ma 1.6.2026
Ensimmäinen viikko          Sinä
Kalenterit                  [Parent A calendar short ID]
                            [Parent B calendar short ID]
```

Calendar IDs are truncated to 40 chars with ellipsis if longer.

**CTA:** "Tallenna ja jatka" (Button variant=default)
**Back:** "Muokkaa" (Button variant=ghost) — returns to Step 1 (not Step 2, user re-navigates forward if they want to change calendar IDs only).

### Step 4 — Valmis! (Setup complete)

Display typography heading. No card border. Centered layout.

Content:
- Heading: "Asennus valmis!" (Display, 28px, semibold)
- Body: "Perhetiedot on tallennettu. Voit nyt siirtyä aikatauluun."
- Note about inviting second parent (Phase 13 hand-off): `Alert` variant=default with info icon: "Toisen vanhemman kutsuminen on tulossa. Toistaiseksi aikataulua voi käyttää yksin."
- CTA: "Siirry aikatauluun" (Button variant=default, links to `/dashboard`)

## Interaction States

| State | Behaviour |
|-------|-----------|
| Wizard page load | Show Step 1 by default; if family_config exists, redirect to /dashboard |
| Continue button clicked, validation passes | Advance to next step; scroll to top of card |
| Continue button clicked, validation fails | Show inline Alert below each failing field; do not advance; scroll to first error |
| "Tallenna ja jatka" clicked | Show loading spinner on button (disabled state) while Server Action runs; advance to Step 4 on success |
| Server Action error | Show Alert at top of Step 3 card: "Tallennus epäonnistui. Tarkista tiedot ja yritä uudelleen." |
| Calendar combobox loading | Trigger spinner inside combobox trigger; populate list when resolved |
| Calendar selected via combobox | Auto-fill read-only ID field below selector with raw calendar ID |
| "Lisää lapsi" clicked | Append new Input row to children list, auto-focus new input |
| Remove child clicked | Remove that row; if only one child remains, disable remove button (at least one required) |
| Start date picker | Disable all days except Mondays; default selected date = next upcoming Monday |
| Back navigation | Return to previous step; preserve all field values (controlled state) |

## Accessibility Contract

- All form fields have `<Label>` with `htmlFor` pointing to input `id`.
- Error messages are associated with inputs via `aria-describedby`.
- Step indicator uses `aria-current="step"` on the active step.
- Remove child button has `sr-only` text: "Poista [lapsen nimi]".
- Calendar picker restrictions (Mondays only) use `disabled` prop on shadcn Calendar — no bypass needed.
- Color is not the sole indicator of validation state — each error uses icon + text message (not just red border).
- CTA loading state: `aria-busy="true"` on the button, `disabled` attribute applied to prevent double-submit.
