<objective>
Fix the build-time env var validation so the Vercel build (and local builds) fail loudly when any required env var is missing, and document every env var that the production deploy needs.

Purpose: DPLY-04 — current `scripts/generate-app-config.js` silently exits 0 when env vars are missing, causing Vercel to deploy a `src/config/app.ts` with `undefined` values. This plan changes that to exit 1 with a FATAL message, adds dotenv loading so local `npm run build` works from `.env.local`, locks dotenv as a direct devDependency (it is currently transitive only via shadcn), and brings `.env.example` up to parity with what `generate-app-config.js` actually requires.

Output: A build script that aborts on misconfiguration, dotenv pinned in package.json, and an `.env.example` that lists every var the Vercel deploy needs.
</objective>
