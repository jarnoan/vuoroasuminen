## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, icon `mt-0.5` nudges |
| sm | 8px | Compact element spacing, `gap-2` between icon and text |
| md | 16px | Default element spacing, card internal padding (`p-4`) |
| lg | 24px | Section padding, wizard step card padding (`p-6`) |
| xl | 32px | Layout gaps between major sections |
| 2xl | 48px | Major section breaks on invite page |
| 3xl | 64px | Page-level vertical spacing (invite error page centering) |

Exceptions:
- Avatar image: 32px × 32px (matches existing header pattern)
- Copy-to-clipboard button touch target: minimum 44px height (accessibility requirement for mobile)
- Invite URL input: full width within its container (`w-full`)

Source: Established in existing wizard components (`p-6`, `space-y-6`, `gap-3`, `gap-4`) — preserve pattern.

Accent reserved for:
1. "Kopioi linkki" (copy invite link) primary button in StepComplete

## Surface Inventory (per screen)

### Surface 1: StepComplete (updated) — `/setup`, step 4

Replaces the placeholder "inviting is coming" alert with an actual invite URL.

Layout: centered, `text-center space-y-6 max-w-lg mx-auto`

Elements:
- `<h1 className="text-3xl font-semibold">` — "Asennus valmis!"
- `<p className="text-muted-foreground">` — confirmation body text
- Invite URL block:
  - `<p className="text-sm font-semibold text-left">` — label for the URL field
  - Row: `<Input readOnly value={inviteUrl} className="text-sm font-mono" />` + `<Button>` with `<Copy />` icon — side by side using `flex gap-2`
  - `<p className="text-sm text-muted-foreground text-left">` — instruction copy below the row
- `<Link href="/dashboard">` styled as `buttonVariants({ size: "lg" })` — "Siirry aikatauluun"

State: copy button shows `<Check />` icon for 2 seconds after clipboard write, then reverts to `<Copy />`. No toast.

### Surface 2: Dashboard invite section — `/dashboard`

Shown only when Parent B has NOT yet joined (no `user_google_tokens` row for `parent2_email`).

Layout: card block within the dashboard page, before or above the main schedule shell. Use existing `bg-card rounded-lg border p-6` pattern (matches wizard step cards). Full width within the dashboard layout, not wider than `max-w-lg`.

Elements:
- Section heading: `<h2 className="text-base font-semibold">` — "Kutsu toinen vanhempi"
- Status line: `<p className="text-sm text-muted-foreground">` — shows link status (active with expiry, expired, or used)
- Invite URL row (same as StepComplete): `<Input readOnly>` + copy `<Button>` with `<Copy />` icon
- "Luo uusi linkki" secondary action: `<Button variant="outline" size="sm">` with `<RefreshCw />` icon
- `<Separator />` not needed — the card border suffices

When link is expired or used:
- Input shows disabled/grayed state (`disabled` attribute, `opacity-50`)
- Status line: `text-destructive` color for the expired/used label
- "Luo uusi linkki" button remains active (generates fresh token, replaces this section's data)

Hidden state: when Parent B has joined, section is removed from the DOM entirely (Server Component conditional render).

### Surface 3: `/invite/<token>` route — token validation page

Two sub-states:

**Valid token:**
Layout: `flex min-h-screen items-center justify-center` (matches existing auth error page)

Elements:
- `<div className="text-center space-y-6 max-w-md px-6">`
- `<h1 className="text-2xl font-semibold">` — "Liity vuoroasumissuunnitelmaan"
- `<p className="text-muted-foreground">` — brief invitation explanation
- Sign-in button: `<Button size="lg">` with `<LogIn />` icon — "Kirjaudu Google-tilillä"
- No form fields; clicking button triggers `signInWithOAuth` redirect

**Invalid / expired / used token:**
Layout: same as valid but shows error content

Elements:
- `<Alert variant="destructive" className="text-left">` with `<AlertCircle />` icon
- Heading within alert: bold inline text
- Body: explanation + instruction (see Copywriting below)
- No CTA button (user must contact Parent A for a new link)

### Surface 4: `/auth/error` — unrecognised email variant

Extends the existing auth error page with a new error variant for "unrecognised email" (D-12).

Layout: existing `flex min-h-screen items-center justify-center` — do not change.

Elements:
- Add a Finnish heading above the existing `<p>`: `<h1 className="text-xl font-semibold">` — "Pääsy estetty"
- `<p className="text-muted-foreground">` — "Tämä tili ei kuulu tähän perheeseen."
- `<p className="text-sm text-muted-foreground">` — secondary instruction copy
- No retry/sign-in button for this variant (session is already signed out by middleware; button would re-trigger the same rejection)

Detection: pass error type via query param `?error=unauthorized_email`. If not present, show existing retry button (calendar scope error).

## Interaction States

### Copy-to-clipboard button
- Default: `<Copy className="h-4 w-4" />` icon, `aria-label="Kopioi linkki leikepöydälle"`
- After copy (2s): `<Check className="h-4 w-4 text-green-600" />` icon, `aria-label="Linkki kopioitu"`
- Reverts automatically via `setTimeout(2000)` — no manual dismiss needed
- Implementation: local `useState<boolean>` in the component, no external state

### Generate new link button
- Default: `variant="outline" size="sm"`, icon `<RefreshCw className="h-4 w-4" />`
- Loading: `<Loader2 className="h-4 w-4 animate-spin" />` icon, button `disabled`
- On success: new invite URL populated in the Input, status line updates to new expiry
- On error: `<Alert variant="destructive">` inline below the section with error message

### Sign-in button on `/invite/<token>`
- Default: idle
- Loading: `<Loader2 className="h-4 w-4 animate-spin" />` prefix, button `disabled`
