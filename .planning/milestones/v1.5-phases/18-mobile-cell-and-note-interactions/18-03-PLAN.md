  <how-to-verify>
    Before starting:
    - Confirm dev server is running locally — `npm run dev` at http://localhost:3000.
    - Confirm Plan 18-01 and 18-02 commits appear in `git log --oneline -10`.
    - For SC-2 vibration (UI-04 D-08), a real phone is required; DevTools Device Mode shows the visual fade and the armed snap but cannot vibrate. The operator may complete vibration verification on a separate session if a phone is not immediately available; the rest of UI-04 can be verified in DevTools.

    ### Mobile checks (DevTools Device Mode, viewport 360–430px, OR real phone)

    **SC-1 — Pen icon on the note affordance button:**
    1. Find a day row whose `Muistiinpanot` column is empty.
    2. The icon in the rightmost mobile cell of that row MUST be a pencil glyph (slanted pen with eraser) — not a plus sign.
    3. Tap the pencil icon. The note input row MUST appear directly below the day row.

    **SC-2 / SC-3 — Long-press Tyhjennä full-cell (vibration requires real phone):**

    Pick a published or draft custody cell (a colored blue or rose cell).

    4. Press and hold (do not move) the cell. Over the next 1s, the background MUST visibly fade FROM the parent color (blue/rose) TOWARD red. The text inside MUST stay the parent's name during the fade.
    5. At ~1s, on a real phone, the phone MUST vibrate once (~100ms pulse). The cell MUST snap to a solid red background with white "Tyhjennä" text. Note: in DevTools Device Mode, only the visual snap is observable; vibration cannot be felt.
    6. With the cell now showing red "Tyhjennä", tap anywhere on the cell. The cell MUST become empty (returns to the gray dashed/empty state shown by the `—` button).

    Repeat the setup, releasing before 1s:

    7. Press and hold a colored cell, then release after ~300–500ms. The cell MUST snap back to its parent color INSTANTLY — no fade-back animation, no lingering red tint.

    Repeat the setup, waiting out the auto-disarm:

    8. Press and hold until the cell arms (red "Tyhjennä"). Do not tap. After ~2s, the cell MUST auto-revert to its parent color and the parent name returns.

    **SC-5 — Note row attribution on mobile:**

    9. Find any day row that has a note (or use the pencil icon to add one).
    10. The note input row MUST sit directly under the day row with no visible vertical gap between them.
    11. The note input's left edge MUST be indented so it sits visually under the date column's text (not flush with the table's left edge).
    12. There MUST NOT be a horizontal divider line between the day row and the note row. The divider line MUST reappear between the note row and the next day's day row.

    ### Desktop checks (browser at ≥640px width, mouse pointer)

    13. Hover over a colored custody cell. The corner × button MUST appear in the top-right of the cell (same as before Phase 18). Clicking the × MUST clear the cell.
    14. Hold the mouse button down on a colored cell for 2+ seconds without moving. The cell MUST NOT fade to red, MUST NOT show "Tyhjennä", and MUST NOT trigger any clear. (This proves the long-press flow is suppressed on hover devices per D-04.) — SC-4.
    15. The desktop notes column ("Muistiinpanot") MUST continue to render the NotesCell inline in the day row, NOT as a second row below.
    16. No visible layout shift in the table compared to before Phase 18.

    Map findings to Phase 18 success criteria:
      - SC-1 (pen icon on mobile note button) ↔ Step 1–3.
      - SC-2 (long-press triggers vibration and full-cell Tyhjennä on mobile) ↔ Step 4–5.
      - SC-3 (tapping Tyhjennä clears the cell; auto-disarm timeout applies) ↔ Step 6, 8.
      - SC-4 (desktop hover × clear behavior unchanged) ↔ Step 13–14.
      - SC-5 (note row visually attributed to its day row on mobile) ↔ Step 9–12.

    Report any failures with: viewport size, browser, specific success-criterion ID that failed, and a screenshot or short description.
