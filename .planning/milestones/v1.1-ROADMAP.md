# Milestone v1.1: Schedule Window Control

**Status:** ✅ SHIPPED 2026-05-06
**Phases:** 5–7
**Total Plans:** 9

## Overview

Gives both parents flexible control over what date range the schedule shows — past, present, and future — plus the ability to add new weeks and clear assignments. Builds on the v1.0 MVP foundation.

## Phases

### Phase 5: View Window Control

**Goal**: Each parent can independently control how far back the schedule view starts
**Depends on**: Phase 4
**Requirements**: VIEW-01, VIEW-02, VIEW-03, VIEW-04
**Plans**: 4 plans

Plans:
- [x] 05-01: Refactor backend data layer (getWindowBounds, getScheduleWindow, page.tsx) to accept viewStart URL param
- [x] 05-02: Install shadcn popover and calendar components
- [x] 05-03: Create ViewToolbar Client Component and loading.tsx skeleton
- [x] 05-04: Wire ViewToolbar into DashboardShell; remove legacy TodayButton

**Success Criteria delivered:**
1. Schedule view starts from Monday of current week by default ✓
2. "Show previous week" button extends view one week back; repeatable ✓
3. User can pick an explicit start date via date picker ✓
4. Preference is per-user — other parent unaffected ✓

**Key decisions:**
- viewStart stored as URL param (not DB) — simple, shareable, no write needed
- ViewToolbar wired between header and publish bar in DashboardShell
- today-button.tsx deleted outright; ViewToolbar's Tänään button replaces it
- VIEW-04: per-user preference via URL param — each browser session independent

### Phase 6: Extend Schedule

**Goal**: Either parent can generate new weeks of schedule beyond the current end date, pre-filled with the alternating default pattern
**Depends on**: Phase 5
**Requirements**: EXTEND-01, EXTEND-02, EXTEND-03
**Plans**: 2 plans

Plans:
- [x] 06-01: extendSchedule Server Action and backend data layer
- [x] 06-02: ExtendPanel client component wired into DashboardShell

**Success Criteria delivered:**
1. "+ Lisää viikkoja" button adds new entries pre-filled with alternating-week defaults ✓
2. Live date range preview shown before confirming ✓
3. User can specify explicit end date instead of week count; Sunday snap applied ✓

**Key decisions:**
- Inline expand panel (not Dialog) — no modal needed for this flow
- fi locale aliased for date-fns and react-day-picker separately
- scheduleEndDate prop from page.tsx getScheduleEndDate() query — not view window end
- rangeEnd snaps to Sunday (endOfWeek with weekStartsOn: 1)

**Bug fixed during UAT:**
- scheduleEndDate was passing view window end instead of actual DB max date; fixed by threading getScheduleEndDate() from page.tsx

---

### Phase 7: Clear Entries

**Goal**: Either parent can remove child assignments from individual cells or date ranges, leaving them unassigned
**Depends on**: Phase 6
**Requirements**: CLEAR-01, CLEAR-02
**Plans**: 3 plans

Plans:
- [x] 07-01: Schema + Server Actions foundation (nullable parent_id, clearCell, clearRange)
- [x] 07-02: Cell × button UI (onClear prop, handleClear, handleAssignEmpty)
- [x] 07-03: Bulk clear panel (ClearPanel component, DashboardShell integration)

**Success Criteria delivered:**
1. Single cell clear via × hover button — empty/unassigned state with no parent color ✓
2. Date range bulk clear via ClearPanel — all child assignments in range cleared ✓
3. Cleared cells are distinct (no color), sync correctly through draft/publish ✓

**Key decisions:**
- parent_id widened to nullable (string | null) in schema, types, and GCal sync
- "unassigned" represented as null parent_id (not deleted row) — draft row preserved
- ClearPanel takes no props — self-contained; no router navigation on success
- queueMicrotask focus restoration to trigger button after collapse
