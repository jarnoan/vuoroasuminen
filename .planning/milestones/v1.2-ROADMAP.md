## Milestone Summary

**Key Decisions:**
- `prompt:consent + access_type:offline` on every sign-in — prevents `invalid_grant` (discovered in v1.0 testing)
- `provider_refresh_token` readable only once: inside `/auth/callback` during `exchangeCodeForSession`
- Middleware uses `getUser()` not `getSession()` — `getSession()` trusts spoofable cookie
- Supabase client NOT initialized at module scope in middleware — Vercel warm instances share scope
- `withRLS` wrapper uses `set_config(..., TRUE)` (transaction-local) — never FALSE
- GCal sync always uses admin Drizzle (service_role) for `user_google_tokens` reads — bypasses RLS by design (D-07/D-10)
- Auth.js table drop order: verificationTokens → sessions → accounts → users (FK chain)
- GATE pattern between phases: Phase 8 GATE before Phase 9, Phase 9 GATE before Phase 10
- RLS policies: domain tables use `USING (auth.role() = 'authenticated')` — per-household isolation deferred
- `user_google_tokens` uses `(auth.jwt() ->> 'email') = email` — per-user isolation

**Technical Debt Incurred:**
- CR-01 (Phase 09): Realtime channel subscribed even when no session — `if (!session?.access_token) return` guard missing
- WR-02 (Phase 09): DELETE policies on domain tables allow either parent to delete other's rows — no ownership column
- WR-03 (Phase 09): `policies.sql` non-idempotent — needs `DROP POLICY IF EXISTS` prefixes
- IN-01 (Phase 09): `console.log` PII (email) in auth callback
- Git history scrub still pending: `src/config/app.ts` contains real email addresses (CR-01 from Phase 10 review)
- RLS-03 Supabase Dashboard impersonation test not completed — requires Pro plan
