<objective>
Fix the invalid_grant error in GCal sync caused by the JWT refresh callback not writing updated tokens back to the accounts DB table.

Purpose: The GCal sync action reads access_token and refresh_token from the accounts table (not from the JWT cookie). When the JWT callback refreshes an expired token, it only updates the cookie — the DB still holds the original (now-revoked) tokens. This causes invalid_grant on the next GCal sync call.

Output: A working token persistence loop (DB stays in sync with JWT cookie) and a clear-tokens utility script for resetting OAuth state during development.
</objective>

```typescript
// Persist refreshed tokens to DB so GCal sync reads valid tokens
const updatePayload: Record<string, string | number> = {
  access_token: newTokens.access_token,
  expires_at: Math.floor(Date.now() / 1000 + newTokens.expires_in),
}
if (newTokens.refresh_token) {
  updatePayload.refresh_token = newTokens.refresh_token
}
db.update(accounts)
  .set(updatePayload)
  .where(
    and(
      eq(accounts.provider, "google"),
      eq(accounts.providerAccountId, token.sub as string),
    ),
  )
  .catch((err) => console.error("[Auth] Failed to persist refreshed tokens:", err))
```

Place this code block immediately before the `return { ...token, access_token: ..., expires_at: ..., refresh_token: ... }` statement inside the `try` block, so it runs only on successful refresh.
