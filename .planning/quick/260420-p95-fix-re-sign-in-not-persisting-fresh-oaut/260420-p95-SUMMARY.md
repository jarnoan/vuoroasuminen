# Quick Task 260420-p95: Fix Re-Sign-In Not Persisting Fresh OAuth Tokens

**One-liner:** Fire-and-forget `db.update(accounts)` on jwt callback sign-in path so GCal sync reads valid tokens after re-sign-in.

## What Was Done

When a user signs out and back in, Auth.js calls the `jwt` callback with an `account` object containing fresh OAuth tokens. Previously the code only updated the JWT cookie — the `accounts` DB row was left untouched. `GCal sync reads tokens from the DB`, so it would get stale/revoked tokens until the next automatic refresh cycle triggered.

Added a fire-and-forget `db.update(accounts)` inside the `if (account)` branch, immediately before the `return` statement. This mirrors the existing refresh-path pattern (lines 53-61 of the original file) and uses `account.providerAccountId` directly (available on the account object) rather than `token.sub`.
